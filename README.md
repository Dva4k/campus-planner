
# Campus Planner

Campus Planner — мобильное приложение для планирования учебных задач. Оно позволяет студентам создавать задачи, отслеживать их выполнение, устанавливать приоритеты и управлять учебной нагрузкой.

## Предметная область

Планировщик учебных задач (Campus Planner).

## Основные возможности

- Авторизация пользователей через API.
- Сохранение авторизованной сессии.
- Получение списка задач с сервера.
- Создание новых учебных задач.
- Просмотр подробной информации о задаче.
- Редактирование существующих задач.
- Удаление задач с подтверждением.
- Поиск задач по названию и предмету.
- Фильтрация по статусу выполнения.
- Сортировка задач по приоритету.
- Изменение статуса задачи с помощью свайпа.
- Анимация карточек и индикатора прогресса.
- Светлая и тёмная темы оформления.
- Обработка ошибок API и неавторизованной сессии.

## Установка и запуск

1. Склонировать репозиторий:

   ```bash
   git clone <ссылка-на-репозиторий>
   ```

2. Перейти в папку проекта:

   ```bash
   cd campus-planner-main
   ```

3. Установить зависимости:

   ```bash
   npm install
   ```

4. Создать файл `.env` в корне проекта на основе `.env.example`.

5. Указать адрес учебного API:

   ```env
   EXPO_PUBLIC_API_URL=https://campus-api.mkseva.workers.dev
   ```

6. Запустить приложение:

   ```bash
   npx expo start
   ```

## Работа с API

Приложение взаимодействует с сервером через REST API.

Используемые запросы:

| Метод | Адрес | Назначение |
|---|---|---|
| POST | /auth/login | Авторизация |
| GET | /auth/me | Получение текущего пользователя |
| GET | /tasks | Получение списка задач |
| GET | /tasks/:id | Получение конкретной задачи |
| POST | /tasks | Создание задачи |
| PATCH | /tasks/:id | Редактирование задачи |
| DELETE | /tasks/:id | Удаление задачи |

Для доступа к защищённым запросам используется Bearer Token, который передаётся в заголовке Authorization.

## Собственная функция

В приложение добавлена сортировка учебных задач по приоритету.

Пользователь может включить или выключить сортировку с помощью отдельной кнопки на главном экране.

При включённой сортировке задачи отображаются в следующем порядке:

1. Высокий приоритет.
2. Средний приоритет.
3. Низкий приоритет.

Сортировка выполняется на стороне приложения и не требует дополнительных запросов к серверу.
